# 康泰克采样备份

Use this skill for backing up large, mostly static instrument or sample libraries. Do not assume the source has a `Kontakt`, `Standard`, or `Nonstandard` directory. Treat a library as one independently restorable source directory. This skill creates archives; it does not relocate, delete, or modify source libraries, upload to cloud storage, or restore Kontakt registration.

The helper is [scripts/archive.py](scripts/archive.py). Run `python3 scripts/archive.py --help` for syntax. It requires `zip` with split-archive support and `7zz`. Store all generated packages on the destination disk, never in SSD scratch space.

## Workflow

1. Obtain or confirm the absolute source directory and destination archive root. Run `scan --source SOURCE --depth 3` first. Inspect its actual branches, loose files, symlinks, and whether any top-level folder is itself a library. Never infer unit boundaries only from directory names.
2. Write a small rules JSON for the observed tree. Each rule is `{"path":"relative/subtree","unit_depth":N}`: depth 0 archives the subtree itself; depth 1 archives each immediate child directory; depth 2 archives its grandchildren. A mixed tree can have multiple rules. Example *only when observed*: `{"rules":[{"path":"Standard","unit_depth":1},{"path":"Nonstandard","unit_depth":2}],"symlinks":"reject"}`. Rules must cover every source file except `.DS_Store`; `plan` rejects uncovered files, overlapping units, and symlinks under the default `reject` policy. Use `"symlinks":"preserve"` only when the user accepts that external link targets are not included.
3. Run `plan --source SOURCE --destination DEST --rules RULES.json --output PLAN.json`. Read the JSON summary and present the proposed unit boundaries, new/changed/skipped counts, estimated additional space, exclusions, destination, 8 GiB split size, and concurrency to the user. Resolve ambiguous grouping before writing any archive. If the user already authorized the backup and the paths and layout are clear, continue after showing the proposal; otherwise ask for the missing decision.
4. Run `run --plan PLAN.json` to execute. Default is five *different libraries* at once on this Mac; `--jobs 3` or `--jobs 4` can be used for a slower disk. Each worker writes a separate destination-side staging folder, runs `7zz t`, checks the source metadata fingerprint again, and atomically moves the whole package folder into `packages/` before recording it in `sample_archive_manifest.json`. A rerun skips unchanged verified packages. Report completed, failed, and skipped counts; do not claim a staging package is complete. After each verified record, the destination also receives `AGENT_采样库恢复指南.md` and a portable `restore_sample_libraries.py`; confirm both exist before calling a backup self-contained.

ZIP uses store-oriented `-1` compression and 8 GiB split volumes; audio samples commonly compress poorly. Keep every `.z01`, `.z02`, etc. beside its `.zip` entry. The manifest maps sanitized package names back to exact original relative source paths, records verification time, and supports later selective restoration. A metadata fingerprint (names, file sizes, modification times, symlink targets) detects ordinary updates, but is not a cryptographic proof of unchanged contents. Use a new baseline or a separate byte-level audit if timestamps might have been deliberately preserved across edits.

If a destination has the old `ARCHIVE_LOG.tsv` but no new manifest, `plan` reports it and `run` stops. After reviewing the old log and source mapping, use `adopt-legacy --plan PLAN.json` as a one-time bridge. It runs `7zz t`, lists each old ZIP, and reads each current source file to compare its CRC32, size, and inventory to the archived entry. This can take hours on multi-terabyte libraries but needs no duplicate archive space. Matching libraries become baseline entries; mismatches are reported in `legacy_unmatched` and may be re-archived after making a new plan. CRC32 is a ZIP integrity check, not a cryptographic identity proof; use bytewise comparison if that stronger claim is needed. Do not silently trust old ZIPs or blindly re-archive the entire source to a near-full disk. If old and new datasets are unrelated, choose a fresh destination instead. After an interrupted run, first rerun the same plan: valid staging packages are verified and promoted, while invalid/incomplete staging stays untouched and is reported. Use `--retry-incomplete` only after inspecting the specific failed staging package; it moves that generated package to `.failed/` before rebuilding it. Never run two archive instances against the same destination.

For restoration on another computer, the Agent should read the generated guide at the backup root and use the bundled helper without installing this Skill. The helper maps each `source_relpath` under a user-selected new root, verifies all parts and the ZIP before extraction, and refuses to overwrite existing libraries. Extraction restores files, not Kontakt's registration state or external symlink targets.
